# LinQ Guard — видеоконтроль нарушений ТБ на ускорителе LinQ

Веб-сервис для производства: по видео с камер находит опасное поведение людей, подтверждает нарушение
во времени и присылает **одно** оповещение с кадром-доказательством. Журнал событий служит доказательной
базой для службы охраны труда, аналитика показывает, где и когда нарушают чаще всего.
Нейросети — архитектуры из списка поддерживаемых SDK LinQ, постпроцессинг общий для GPU и TPU.

Кейс хакатона «Открой Моспром», постановщик — LinQ.

## Архитектура

```
Источники ──► Детекторы (ONNX / TPU LinQ) ──► Постпроцессинг YOLO (numpy) ──► Трекер
   │                                                                          │
   │          Правила-плагины по зонам и расписаниям ◄────────────────────────┘
   │                          │
   │                Менеджер событий: окно подтверждения, доля кадров, удержание, кулдаун, склейка ID
   │                          │
   └──► Веб (FastAPI): кадры по WebSocket, лента, галерея, журнал (SQLite), аналитика, зоны, метрики
```

- `engine/postprocess.py` — letterbox и декодирование выхода YOLOv8/YOLO11 (detect и pose) с NMS на numpy.
  Тот же код обрабатывает выход хвоста модели после TPU.
- `engine/backends.py` — `OnnxBackend` (CUDA/CPU) и `LinqTpuBackend` (pytpu + хвост ONNX на CPU).
- `engine/rules/` — нарушения. Новое нарушение — новый класс с декоратором `@register`, ядро не меняется.
- `engine/events.py` — превращает покадровые сигналы в события; подробности в docstring.
- `configs/cameras/*.yaml` — камеры, модели, зоны, правила, расписания, калибровка пола.
- `api/` — веб-сервис и интерфейс (без сборки фронтенда).

## Запуск

На сервере с GPU (Linux x86-64):

```bash
uv venv --python 3.12 .venv && . .venv/bin/activate
uv pip install --index-url https://download.pytorch.org/whl/cu124 torch torchvision
uv pip install ultralytics onnx "onnxruntime-gpu==1.22.0" opencv-python-headless fastapi "uvicorn[standard]" pyyaml
python tools/export_models.py --models /workspace/linq/models    # ONNX 640×640 со статичным входом
tools/run_server.sh                                               # порт 8000
```

С ноутбука: `ssh -p <порт> root@<сервер> -L 8000:localhost:8000`, затем http://localhost:8000.

Тесты движка: `python -m pytest`.

## Модели и данные

| Модель | Классы | Источник | Лицензия |
|---|---|---|---|
| YOLOv8n-pose | человек, 17 точек | Ultralytics | AGPL-3.0 |
| YOLOv8s | транспорт, телефон (COCO) | Ultralytics | AGPL-3.0 |
| YOLOv8 PPE | каска, без каски, жилет, без жилета, техника | HF `Hansung-Cho/yolov8-ppe-detection` | MIT |
| YOLOv8n forklift | погрузчик | HF `keremberke/yolov8n-forklift-detection` | не указана |
| YOLOv8n fire-smoke | огонь, дым | HF `rabahdev/fire-smoke-yolov8n` | AGPL-3.0 |
| YOLO cigarette | сигарета | HF `Beehzod/best_smoke_cigarette-detection` | MIT |

Демо-видео: бесплатные ролики Mixkit (лицензия Mixkit Free) и записи падений из UR Fall Detection Dataset
(исследовательский набор). Из роликов собраны семь «камер» по участкам: стройплощадка, склад, цех, коридор АБК,
ворота у склада ГСМ, сварочный пост, проходная.

Для продукта лицензию AGPL нужно заменить: архитектуры с Apache-2.0 (DAMO-YOLO, YOLOX, RTMDet) или коммерческая лицензия Ultralytics.

## LinQ

- Все модели экспортируются в ONNX с фиксированным входом 1×3×640×640 — требование SDK.
- YOLOv8n-pose есть в списке поддерживаемых моделей SDK; детекторы — того же семейства YOLOv8.
- Голова YOLO отрезается `get_sub_model`: TPU считает сеть до decode, хвост и NMS выполняет CPU тем же кодом.
- Калибровка квантования — на реальных кадрах камер, а не на случайных данных из примера SDK.
- Замеры: экран «LinQ» показывает задержку каждой модели по этапам (препроцессинг, инференс, постпроцессинг).

## Ограничения

- Демо работает на видеофайлах; на объекте источники — RTSP с IP-камер.
- Без калибровки пола расстояния и скорости считаются в ростах человека, а не в метрах.
- Узкие детекторы с Hugging Face обучены на чужих данных; на объекте их нужно дообучить на кадрах своих камер.
