2. **Замер на настоящем LinQ** — поднять VPN, прогнать `linq/bench.py` на стенде хотя бы для позы и одного детектора (задержка p50/p95, FPS, две программы на одном устройстве), вписать на экран «LinQ» и в слайд. Ограничить часом; если VPN не поднимется — честный слайд «скомпилировано + эмулятор».
3. **Журнал по букве требования** — фильтр по зоне и интервал «с–по» (`store.query` + селект в `app.js`), CSV по текущим фильтрам; в карточке и в боте показывать номер камеры.
4. **SLA-отчёт по реакции** — из таблицы `alarms` (`ack_at`, `resolved_at`, `escalated_at`): медиана «принял» и «устранено», доля устранённых в срок, эскалации, просроченные; вывести в сводку смены, отчёт конца смены и экран руководителя.
5. **Роль оператора** — назвать веб-пульт «рабочее место оператора»; статус «передано мастеру» (или кнопка в ленте) поднимает тревогу в боте у начальника смены для некритичных событий; добавить роль в README/слайд ролей.
6. **Калькулятор LinQ** — на экране «LinQ»: камер на ускоритель при 5 кадрах/с и N моделях → сколько H1M на мастерскую из 5 камер и на цех из 100 камер; рядом TPU / GPU / CPU (задержка, кадров/с, Вт).
7. **Доступ для экспертов** — открыть веб-пульт по публичной ссылке под демо-паролем (Basic Auth) или только на чтение; закрепить адрес (именованный туннель или VDS), чтобы ссылка в ЛК не умерла после перезапуска.

Если останется время: источник «папка снимков» (О1), выгрузка ложных и подтверждённых кадров для дообучения (Ж4), точность по камере и правилу.

## 6. Что жюри захочет УВИДЕТЬ за 3 минуты

1. **Живая тревога**: ролик идёт как камера → через 1–3 с карточка в ленте (кадр с выделенным человеком, ролик, камера, время, тип) и одновременно фото в Telegram у начальника смены.
2. **Одно нарушение — одно оповещение**: человек без каски стоит дольше минуты, в ленте одно событие с растущей длительностью, в боте одно сообщение.
3. **Цикл реакции**: «Принял» → «Устранено» с коротким отчётом → время до устранения; неустранённая тревога уходит руководителю (эскалация за 1 мин в демо-настройке) и SLA-цифры смены.
4. **Кто нарушил**: событие привязано к «Сотруднику №N» по лицу; рабочий в конце смены получает свои нарушения и CSV.
5. **Разбор смены**: длинная запись → ролики по категориям, критичные сверху, подтверждение и отклонение с клавиатуры, отчёт.
6. **Настройка без кода**: полигон опасной зоны мышкой на кадре, расписание зоны.
7. **Дашборд**: по типам, камерам, час × день, текстовая сводка с рекомендациями.
8. **LinQ**: программы `.tpu`, проверка квантования (поза 99% людей FP32), цифры с настоящего TPU, сравнение с GPU/CPU и «сколько ускорителей на цех».
9. **Качество в цифрах**: P/R/F1 и взвешенное по тяжести покрытие; каски mAP50 0,93 против 0,29 у открытой модели.
10. **Расширяемость**: одно новое правило — один файл с `@register` и строка в YAML камеры.
