# Фильм «Смена 24.10»

Ролик для защиты: одна смена цеха, 9 тревог, 10 видов нарушений. Каждая тревога показана одинаково: живой кадр камеры,
рамка нарушителя, кольцо подтверждения, карточка бота в Telegram, «Принял», «Устранено». В конце — итог смены.
Готовое видео лежит в релизе [v1.1.0](https://github.com/PhantomDev2059/mosProm/releases/tag/v1.1.0):
`linq_guard_shift_film.mp4` (1080p) и `linq_guard_shift_film_720p.mp4`.

## Что в нём настоящее

- **Тревоги** — события конвейера LinQ Guard (`engine/`) на заводских записях демо-смены. Момент тревоги в фильме —
  момент, когда конвейер открыл событие. Все 10 видов: нет каски, нет жилета, телефон, сближение с погрузчиком,
  курение, падение, лежит без движения, бег, открытый огонь, задымление.
- **Рамки** — треки конвейера, сглаженные для показа. Рисуются только треки события; остальные люди в кадре без рамок.
- **Карточки бота** — `api/cards.py`, та же картинка, что приходит начальнику смены.
- **Метры и м/с** у сближения и бега — по калибровке пола камеры (`pipeline/cams.json`).

Монтаж: кадр с огнём замедлен в 2,5 раза. Время смены, «Принял» и «Устранено» условные. Рамка появляется за секунду
до тревоги — так видно подтверждение.

## Калибровка пола

Бег прямо на камеру и сближение сбоку от погрузчика без калибровки не измерить: правила считают сдвиг «в ростах человека»,
а при движении по глубине кадра он почти нулевой. Поэтому двум камерам задана калибровка пола, как при установке на объекте:

- Горизонт и высота камеры — по росту людей в кадре. Рост рамки линейно зависит от нижней кромки, h = 1,75 м × (y − y_гор) / H_камеры;
  точки ложатся на прямую с ошибкой до 11 px.
- Фокусное расстояние — по типу съёмки: К-02 (склад) — широкоугольная камера, 950 px; К-07 (ворота) — длиннофокусная, 2800 px.
- К-02: порог сближения 3 м до движущегося погрузчика (по умолчанию 2,5 м). Расстояние считается до ближайшей точки
  нижней кромки погрузчика, а не до её середины (`engine/rules/person.py`).

На живой демо-смене (одна камера из склеенных роликов) калибровки нет, там правила работают в «ростах».

## Как собрать

`linq-shift/` — проект на движке [procedural-film](https://github.com/kuhnhomeuk-cell/procedural-film) (MIT, `LICENSE-procedural-film`):
плиты «бумага» и «чертёж», тушь, зерно, музыка. Рендер с живыми кадрами камер — `tools/vrender.cjs`.

```bash
# 1. ролики нарушений (вырезаны из demo_all_violations.mp4 по склейкам) → pipeline/clips/
# 2. конвейер по роликам: события и рамки (калибровка из cams.json подхватывается сама)
python pipeline/detect.py . registry.json pipeline/dets.json pipeline/clips/*.mp4
# 3. данные фильма: окна шотов, кадры камер, карточки бота → linq-shift/src/photos.js, timeline.js
python pipeline/shift_data.py . film/linq-shift pipeline/dets.json pipeline/dets_cal.json
# 4. рендер (Playwright + ffmpeg)
cd film/linq-shift/tools && npm install && npx playwright install chromium && cd ..
node tools/vrender.cjs --workers 6 --out exports/linq-shift.mp4
node tools/vrender.cjs --at 7,20.6,44.4 --out .tmp/snap     # отдельные кадры и лист-превью
```

`pipeline/review.py` — лист проверки срабатываний по кадрам, `pipeline/probe_rules.py` — замеры для правил бега и сближения
(скорость, рост рамки, зазор до техники). Рендер 73 с занимает около 3 минут на сервере с 6 вкладками Chromium.
